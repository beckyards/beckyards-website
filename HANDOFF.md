## Current state

Everything below is committed, pushed to `github.com/beckyards/beckyards-website`, and deployed live at `beckyards.com`.

**Public site:** Home, Services (6 pages), Programs (Green+, Spring+, Community+ — the last one income-based pricing for people who can't necessarily afford standard lawn care), About, Portfolio, Contact, Terms, and a dedicated Aeration & Overseeding Signup flow. Header has Services/Programs/Contact dropdowns plus plain About/Portfolio links (Contact's dropdown is right-anchored so it doesn't open on top of the "Free Quote" button). About and Portfolio are both editable from admin Content like every other page — About is a normal text page (Visual + Form + JSON), Portfolio is a photo gallery (Form + JSON only, same list-of-cards pattern as Services/Programs) that starts empty until real job photos are added via Content → Portfolio → "+ Add entry" (drop a photo onto the entry's SRC field or use Pick).

**Admin panel** (`/admin`, login `thebeckyards@gmail.com`) — flat, line-divided visual style (no boxed cards; separators are hairline borders) across every page below:
- **Dashboard** — traffic stats, recent inquiries, quick links to every section.
- **Analytics** — traffic trends, top pages, referrers, devices/countries.
- **Messages** — general contact-form inbox. Each message has an inline **Reply** composer that emails the sender directly via Resend and logs the reply on the thread (`message_replies` table) — no more switching to an external email client. Requires `RESEND_API_KEY` in Vercel; until a real `beckyards.com` sender is verified in Resend, sending is limited to the Resend sandbox's own restrictions (see Outstanding).
- **Aeration List** (`/admin/aeration`) — signups from the public Aeration & Overseeding form. Click-to-edit-in-place, drag-and-drop reordering, a "Done" checkbox, and a running price total. **Contains real customer data — always use `_verify-`-prefixed names for any test rows and delete them immediately after.**
- **Clients** (`/admin/mowing-route`) — the two mowing crews' rosters, Group A and Group B, each a table of name/address/phone/price/mowing-height (2"–5" in 0.25" steps)/payment-type (Venmo/Cash/Check/Bill), click-to-edit-in-place, drag-and-drop reordering, a copy-to-Group-B icon on each Group A row, and a client-count line per group. A collapsible **Misc / Occasional Clients** section holds one-time or infrequent clients (with a free-text `frequency` field like "Once a month"); each can be dragged or button-moved into Group A/B. **Contains real, actively-used client data** (dozens of real names/addresses/prices) — same `_verify-` testing convention applies.
- **Route** (`/admin/route-run`) — the field-use tool. Pick Route A or B to get-or-create *today's* run: a big-tap checklist (name, cut height, price, checkbox) snapshotted from Clients, with a "Who helped on this route?" field and live "Total to make" / "Earned so far" stats. A "Complete Route" button files the run into History and instantly starts a fresh one for that group. Revisiting the same group the same day resumes the in-progress run rather than duplicating it. **History** is built into this same page (below the A/B picker) and lists every *completed* run (date, progress, earned, helper) — click "View" to reopen any past run's exact checklist via `?runId=`.
- **Images** — media library (upload, rename, delete, bulk-select). Uploads accept iPhone HEIC/HEIF photos (auto-converted to JPEG server-side via `heic-convert`). Uploads now go through a signed-upload-URL step (browser → Supabase `enhance-tmp` scratch bucket → server finalizes into `media`), the same pattern Enhance already used — see the 2026-09-17 task log entry for why this, not just the HEIC/wasm fix, was needed for real phone uploads to actually work.
- **Enhance** (`/admin/enhance`) — ported from Oskelo's admin: drop in a photo for one-click auto color/contrast correction, or fine-tune manually (brightness/contrast/saturation/sharpen, rotate, and a paint-on mask to adjust one region of the photo separately from the rest). Nothing is saved until you choose to; save sends the result to Images. Also HEIC-aware. Large originals bypass Vercel's ~4.5 MB body limit via a signed-upload-URL step into a private `enhance-tmp` bucket.
- **Before/After** (`/admin/compare`) — pick two already-uploaded photos (a before and an after shot) via the same picker used on the Content page, label each, choose side-by-side or stacked layout, and generate one combined comparison image (labels burned in) to save to Images.
- **Content** — structured or raw-JSON editor for every page's copy.
- Mobile (<900px): the sidebar becomes a hamburger-triggered slide-in drawer. Below 700px, every admin table renders as a stacked label/value list instead of a horizontally-scrolling table.

**Database** (Supabase project `yvlxgvjlhspvgtytagar`): `aeration_signups`, `mowing_clients` (`route_group` is `'A' | 'B' | 'misc'`, plus `frequency`, `payment_type`, `mowing_height`), `route_runs` (one row per group+day; `route_group`+`run_date` unique while `completed_at is null`, `helper` text field), `route_run_items` (per-run snapshot; `run_id`+`client_id` unique), and `message_replies` (logs each admin reply sent from Messages: `message_id` FK, `to_email`, `body`, `sent_at`). All service-role-only via RLS — no public policies except the aeration signup form's insert. **Storage buckets:** `media` (public, image MIME allowlist) and `enhance-tmp` (private, 60 MB limit, no MIME restriction — scratch space for the Enhance tool's original uploads, cleaned up once a correction is saved).

**Notable bugs found and fixed this build** (kept here since they're the kind of thing that could resurface or recur elsewhere):
- A production-only `"Cannot convert argument to a ByteString"` error on every `/api/admin/*` route turned out to be a single corrupted character (a stray "•" in place of a letter) inside `SUPABASE_SERVICE_ROLE_KEY` in Vercel's env vars — a copy-paste mangling, not a code bug. Local dev never had it since `.env.local` was always correct. Found by adding a temporary route that bypassed supabase-js and made a raw `fetch()` to Supabase directly (postgrest-js normally swallows the real stack trace on network errors, showing only a bare message) — the raw fetch's real error confirmed the corrupted byte. Fixed by deleting the env var and re-entering it through Notepad as a plain-text intermediary.
- Starting a Route run raced under React Strict Mode's intentional double-invoke: two near-simultaneous requests could both think no run existed yet and either create duplicate runs or double-snapshot the same run. Fixed at the database level with a partial unique index (`route_runs`, one open run per group/day) and a unique constraint (`route_run_items`, one snapshot per client per run) — the API now catches either violation and falls back to the concurrent winner's row instead of erroring or duplicating.
- A CSS Grid bug: `.admin-shell` had no explicit `grid-template-rows`, so once the mobile nav/backdrop went `position:fixed` (removed from grid flow), the two remaining in-flow children (mobile top bar + `<main>`) stretched to fill the full `min-height:100vh`, inflating the top bar to double its real height. Fixed with explicit `grid-template-rows: auto 1fr` in the mobile media query.

### 2026-09-15 (yet again) — HEIC upload fix actually didn't work in production — found the real cause

- **Asked:** "for some reason i still cant get photos from my phohone onto the phtos section" — the heic-convert fix from the previous entry was live, but phone uploads were still failing.
- **Root cause:** `heic-convert` → `heic-decode` → `libheif-js` loads a `libheif.wasm` binary (1.4 MB) at runtime via a `__dirname`-relative path built dynamically inside a minified Emscripten bundle — not a statically analyzable `require()`/import. Next.js's serverless file tracing (which decides exactly what files Vercel bundles into each API route's deployed function) can only follow static references, so it silently excluded `libheif.wasm` from both `/api/admin/media` and `/api/admin/enhance`'s deployed functions. This meant every HEIC conversion attempt failed in production with a file-not-found error, while working perfectly in local dev (where the full `node_modules` tree sits on disk regardless of tracing). Confirmed by inspecting `.next/server/app/api/admin/media/route.js.nft.json` after a production build — zero heic/wasm-related files were listed.
- **Fixed** by adding `outputFileTracingIncludes` in `next.config.js`, forcing `./node_modules/libheif-js/libheif-wasm/*.wasm` into the trace for both routes. Rebuilt and confirmed the `.wasm` file now appears in both routes' `.nft.json` trace output.
- **Lesson for future sessions:** any Vercel serverless route that transitively depends on a package loading a binary/WASM asset via a dynamic path (rather than a static `require('./file.wasm')`) needs an explicit `outputFileTracingIncludes` entry, or it will work in local dev and fail silently in production — a gap that's easy to miss since `npm run build` succeeds either way and only Vercel's actual deployed function is affected.
- **Not yet verified against a real iPhone HEIC photo** — no real HEIC sample was available to test with locally, and this class of bug only manifests once actually deployed. Needs the user to try a real phone upload on the live site after this deploys.
